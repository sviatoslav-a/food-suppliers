# Scout

Поиск и сравнение поставщиков продуктов и упаковки для ресторанов. Сделано для второй части тестового задания Goulash.tech.

![Демо: поиск, сравнение и работа с поставщиком](docs/demo/scout-demo.gif)
[Полная запись, MP4](docs/demo/scout-demo.mp4)

Первая часть задания: [портфолио](https://sviatoslav-a.github.io/) ([исходники](https://github.com/sviatoslav-a/sviatoslav-a.github.io)).

## Что умеет

- Ищет по категории, городу или фразе вроде «сыры для пиццы в Екатеринбурге».
- Показывает условия, контакты и ссылки на источники. Объясняет оценку поставщика.
- Сравнивает до четырёх компаний рядом.
- Готовит письмо с вопросами о недостающих условиях. Сам письма не отправляет.
- Сохраняет выбранных поставщиков, заметки, статусы и полученные цены. Их можно выгрузить в CSV.

## Запуск

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```sh
uv sync --frozen
uv run uvicorn scout.web:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000. Готовая база включена в репозиторий; ключи API и повторный сбор данных не нужны.

## Данные и ограничения

В базе 86 поставщиков, найденных на публичных сайтах. Сбор от 13.10.2026, реестр МСП от 10.09.2026. Целевые города: Екатеринбург и Москва. Категории: мясо, рыба, молочные продукты, овощи, бакалея, азиатские продукты, напитки и упаковка.

| Что найдено | Компаний |
|---|---:|
| Телефон или почта | 85 |
| Цены | 34 |
| Минимальный заказ | 46 |
| Условия доставки | 72 |
| Упоминания документов | 46 |
| ИНН совпал с записью ЕГРЮЛ | 38 |

Пустые поля не заполняются выдуманными значениями. Цены и наличие нужно уточнять у поставщика. Документы указаны со слов сайтов; действительность сертификатов не проверялась. Совпадение ИНН с ЕГРЮЛ не подтверждает, кому принадлежит сайт.

Приложение ищет в сохранённой базе, а не в интернете. Шорт-лист хранится только в текущем браузере. Общей работы команды и синхронизации пока нет. Контакты `bubon-horeca.ru` найти не удалось: при повторном обходе сайт был недоступен.

Отчёты о данных: `data/build_report.json` и `data/quality_report.json`. Перед использованием контактов в рабочей системе нужны проверка персональных данных и условий источников.

## Как устроено

FastAPI, Jinja, SQLite и обычный JavaScript. Поиск по тексту использует FTS5 и словарь категорий. Оценка складывается из соответствия запросу, географии, сведений о юрлице и полноты условий. Это способ упорядочить список, не гарантия надёжности компании.

LLM используется при сборе: ищет сайты и извлекает условия. Во время работы приложения модель не вызывается. Веб, JSON API и MCP используют одну логику в `scout/service.py`.

- `/about`: как считаются баллы и откуда взяты данные.
- `/docs`: описание API.
- `/healthz`: проверка работы сервера.

MCP по stdio:

```sh
uv run python -m scout.mcp_server
```

Инструменты: `search_suppliers`, `get_supplier`, `draft_request`. Ресурс `scout://taxonomy` содержит категории и города.

## Проверки и запись демо

```sh
uv run playwright install chromium
uv run pytest -q
uv run python -m pipeline.audit
uv run python tools/record_demo.py  # при запущенном приложении; нужен ffmpeg
```

42 теста проверяют поиск, карточки, источники, сравнение, сохранение заметок, CSV, мобильную вёрстку и MCP. Подробности в [отчёте](docs/verification.md). Запись экрана сохраняется в `docs/demo/`: MP4 1440×900 и GIF шириной 1200 px. Демо не отправляет письма и не меняет базу.

## Повторный сбор

Для запуска демо этот шаг не нужен. Сбор требует сети и авторизованного Claude CLI с доступной квотой. Скачайте ZIP [реестра МСП ФНС](https://www.nalog.gov.ru/opendata/7707329152-rsmp/) в `data/raw/rsmp.zip`, затем:

```sh
uv run python -m pipeline.rsmp
uv run python -m pipeline.discover --workers 2
uv run python -m pipeline.fetch
uv run python -m pipeline.extract --workers 2
uv run python -m pipeline.contacts
uv run python -m pipeline.build
uv run python -m pipeline.audit
```

Исходный реестр, кеши и логи не включены в git. Сборщик проверяет robots.txt, делает паузы между запросами и не обходит CAPTCHA. После пересборки базы перезапустите приложение.
